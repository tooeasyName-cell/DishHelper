# DishHelper

在电脑上使用的饮食生活 AI 助手，支持规划、买菜、备菜与烹饪讨论。程序可保留会话背景和操作步骤，并提供可自行管理的持久化记忆。

## 下载与启动

希望让本地 AI Agent 帮你安装和配置？把 [首次配置指南 AGENT_SETUP.md](AGENT_SETUP.md) 交给它，或复制指南开头的指令。Agent 可按你的选择处理免安装版/源码版启动、本地演示、真实模型配置，以及可选的 AstrBot 手机私聊入口；需要登录和输入密钥时由你在本机完成。指南也包含逐项验收与故障定位，不要求一次配齐所有功能。

0.9.3 同时提供 Windows x64 免安装包和源码包。新版 Windows 包已补齐 HTTPS 初始化所需资源，修复旧包调用外部模型时可能出现的“路径不存在”错误，保留证书和主机名校验。

1. Windows 用户在 [Releases](https://github.com/tooeasyName-cell/DishHelper/releases) 下载 `DishHelper-0.9.3-Windows-x64.zip`，完整解压后双击 `DishHelper.exe`，无需安装 Python；保留同目录的 `_internal` 文件夹。
2. 开发者可下载 `DishHelper-0.9.3-source.zip` 或对应标签的 Source code，准备 Python 3.12+。在解压后的 DishHelper 目录双击 `start.cmd`，首次会创建虚拟环境并安装依赖；也可自行创建虚拟环境，运行 `python -m pip install -r requirements.txt`，再运行 `python launcher.py`。
3. 程序会打开本机浏览器。若没有自动打开，复制启动窗口显示的 `http://127.0.0.1:端口` 地址到浏览器。依赖的固定版本见 `requirements-lock.txt`。

Windows 启动脚本适用于 Windows 10/11 64 位；其它系统可按源码方式自行配置环境，本次未验证。本地演示不需要模型账号；首次安装依赖需要网络，真实 AI 回答需要网络和你自己的模型服务账号。关闭启动窗口或按 Ctrl+C 停止程序。

## 配置模型

首次启动预置本地演示和 DeepSeek 模型档案，并将各场景默认模型设为 DeepSeek。真实 AI 需自行配置对应服务的 API Key；选择“本地演示”可不联网熟悉界面，演示只返回固定样例，不理解输入。已有用户的模型档案和默认选择不会被更新覆盖。

展开侧栏“模型初始设置”，可使用预置的 DeepSeek 档案，或新建 `openai_chat` 档案并填写服务商提供的 Base URL 和模型名称。预置 DeepSeek 档案的凭据引用为 `DEEPSEEK_API_KEY`，在密码框输入自己的 API Key 后保存。仅预置一个近期问答为 0 轮的 DeepSeek 档案，三个场景默认选择该档案；已有用户的模型档案保持原样。

密码框输入的 Key 仅在当前程序运行期间有效。如需重启后继续使用，免安装版在 `%LOCALAPPDATA%\DishHelper\.env`、源码版在项目根目录（与 `launcher.py` 同级）的 `.env` 中写入 `DEEPSEEK_API_KEY=你的密钥`，然后重启；也可自行设置同名环境变量。使用其他模型时，请对应其凭据引用填写环境变量名。请妥善保管该文件，不要随截图、日志或压缩包分享。

支持兼容 OpenAI Chat Completions 的服务，不支持所有服务商的原生协议。调用费用由你的模型服务商收取。程序会发送本轮输入和所需的会话背景，输入前请考虑所选服务商的数据处理规则。

## 日常使用

- 选择日期和场景，输入需求并发送；同一天的不同场景可接收相关共享信息。
- “当前任务背景”保留仍需查阅的步骤或条件；“持续参考”可跳转到详细回复。部分回复会额外调用模型进行阅读排版。
- “共享信息”可查看、编辑或删除记忆；“历史会话”可恢复、导出或删除讨论。
- “近期成功问答轮数 N”可设为 0–20；0 表示不附带近期问答原文，仍会使用工作记忆。
- “状态与请求检查”和版本比较可用于检查模型输入输出。额外比较、排版或整理可能产生模型费用。
- 本版本未提供联网搜索及平台登录功能。

## 记忆与共享信息

程序会保留会话中的任务背景，方便继续讨论；同一天不同场景之间也可以共享相关信息。跨天的“持久共享”用于保留可复用的用户背景，例如长期饮食偏好或常用条件，设计目标是在后续不同日期的会话中减少重复说明。

你可以在侧栏“共享信息 · 当日 / 跨天”查看、编辑或删除条目。持久共享支持整理，只有在你确认后才会调用模型执行；整理完成后可查看记录并按需回退。记忆由模型根据对话提取和整理，是否准确仍需你自行检查。

模型可能出错，请核对影响食品安全的建议。

## 测试提示词

在成功回复下展开“反馈与版本比较”，可选择“场景说明·详细版”比较较长场景说明，或选“自主编辑请求 JSON”，修改 messages 中 role 为 system 的 content 后预览和测试。比较额外调用一次模型，不会自动成为默认提示词，也不会修改原会话记忆。免安装版的默认提示词随程序构建，不能通过编辑旁边的源码文件永久替换。

## 可选 AstrBot 手机入口

配套插件源码位于 `integrations/astrbot_plugin_dishhelper`。也可在本版 Release 下载 `AstrBot-DishHelper-0.9.3.zip`，在 AstrBot 插件管理中以本地 ZIP 安装；安装和配置见该目录的 README。本程序不包含 AstrBot 或 QQ 登录组件，实际平台连接仍需自行联调。已安装配套插件的用户无需因本次主程序更新重新安装插件。

支持由独立运行的AstrBot把绑定私聊文字交给DishHelper。电脑端配置手机接入后，在AstrBot安装配套插件并填写相同的本机地址、连接密钥和私聊来源UMO。接入默认关闭，AstrBot不包含在本程序安装包内。电脑会自动对齐手机选定的日期、场景和会话；手机复用回答正文，标明具体日期，长内容分段发送。临时分支、调试、反馈和配置管理仍在电脑端。

纠正路由会回放上一条原始业务消息，产生新的回答调用；原轮已经写入的记忆和共享信息不会自动撤回。保持两项服务运行即可关闭浏览器；已有旧EXE需更新为包含该功能的新构建。

手机决策支持聊天服务和原生 systemone：原生档案填完整请求URL及可选响应根路径（如result），只用于决策。两者共用规则和答案结构，目标选项评分达到默认0.85才允许普通提问自动转饮食场景；门槛可在手机接入设置调整。无关问题进入独立杂谈，历史沿用业务模型的N，不改变饮食记忆；电脑可在“手机独立杂谈”展开查看，不自动离开饮食页面。当前AstrBot插件无需更换。原生供应商仍需按实际连接联调。

侧栏直接点击“手机路由调试”可在大窗口查看运行状态、决策输入、完整模型回复、评分和最终执行。支持自动刷新、跟随最新消息或固定历史记录，查看不会重新调用模型。

0.9.3仅优化输入缓存结构：聊天路由固定问题在前、动态状态在后，主会话R在C/U前。业务与路由提示词文字不变，原生决策接口不变。状态检查/手机路由调试新增缓存统计；未报告不当作零，百分比仅覆盖已报告的输入与命中用量，实际收益以服务方报告为准。

## 数据、备份与升级

源码版的数据保存在程序目录的 `data` 中；免安装版的数据保存在 `%LOCALAPPDATA%\DishHelper`。两者默认不共用数据库。会话和模型配置保存在 `dishhelper.sqlite3` 中。从旧 EXE 切换到源码版时，若要沿用记录，先停止旧程序并备份，再将原数据目录复制为源码目录下的 `data`；如使用原数据目录中的 `.env`，需放到源码目录根部，按自己的配置核对后启动。

备份时先停止程序，再复制整个数据目录。升级时停止旧程序，将新版本解压到新文件夹并启动；程序会继续使用同一数据目录。不要把仍在运行的数据文件覆盖回去。

“清空使用数据”需要确认，保留模型档案与应用设置；不会删除 `.env` 或已经导出的文件。卸载时删除程序文件夹即可；需要彻底移除记录时，再自行删除上述数据目录。

## 常见问题

- 页面打不开：检查启动窗口中的错误和实际端口。端口占用时程序会尝试其他本机端口。
- 模型调用失败：检查网络、Key、余额、模型名称和服务地址；按页面提示修正后重试。
- 不要只复制 EXE：运行所需文件在 `_internal` 中，必须保留完整文件夹。

## 从源码启动

源码使用者需自行准备兼容的 Python 环境（当前发布构建使用 Python 3.12 x64）。Windows 可双击 `start.cmd`，首次会安装依赖；也可自行创建虚拟环境，安装 `requirements.txt` 后运行 `python -m streamlit run app.py --server.address 127.0.0.1`。源码版默认在项目的 `data` 文件夹保存记录。
